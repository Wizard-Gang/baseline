# Baseline control map

This document maps each baseline control to its committed authority and the evidence required before claiming that the control works. `README.md` describes the repository; `AGENTS.md` and `CONTRIBUTING.md` are the byte-identical portfolio instructions. GitHub's live state is checked separately from source.

| Control | Committed authority | Verification |
| --- | --- | --- |
| Permanent current-only work queue | `implementation_plan.md`, `scripts/change-contract.mjs`, `scripts/check-portfolio-contract.mjs` | `npm run test:plan-queue`, `npm run check:change`; an empty queue selects no implementation task and the next instruction must fill it through a controlled plan-only change. |
| Permanent controlled identity | `scripts/change-contract.mjs`, `docs/CHANGE-MANAGEMENT.md` | One sequential `BASE-###` ID, matching branch/PR/commit, structured body, one PR-range commit, and exactly one squash commit retained on `main`. |
| Shared agent and contributor instructions | `AGENTS.md`, `CONTRIBUTING.md`, `scripts/check-portfolio-contract.mjs` | SHA-256 comparison with the published common contract hashes during `npm run check`. |
| Toolchain and dependency lock | `.node-version`, `package.json`, `package-lock.json` | Node 26.10.0, npm 12.1.0, `npm ci`, repository contract tests. Dependency advisories run separately through `npm run audit:dependencies`. |
| Credential-free local acceptance | `package.json`, `.github/workflows/ci.yml` | `npm run check` runs tests, source and policy validation, and controlled history without a GitHub token. |
| Exact-head required CI | `.github/workflows/ci.yml`, `config/github-repository-settings.json` | `verify`, `change-id`, and `security` run on the exact PR head. `verify` checks the committed patch; `security` runs the separate advisory gate. All three are required and current with `main`. |
| Repository identity | `config/github-repository-settings.json`, `scripts/github-repository-settings.mjs` | The verifier compares the live full repository name and `main`; environment variables cannot redirect the target. |
| Squash-only merge topology | `config/github-repository-settings.json`, `scripts/github-repository-settings.mjs` | Repository merge commits disabled, squash enabled, rebase disabled; the main ruleset derives `allowed_merge_methods` from the same committed `mergeMethods` object. |
| Auto-merge availability | `config/github-repository-settings.json`, `scripts/github-repository-settings.mjs` | `allowAutoMerge: true` matches live `allow_auto_merge`. This makes per-PR auto-merge available; it does not enroll a PR automatically. A controlled PR uses squash and retains exact-head CI and the controlled commit record. |
| Completed branch cleanup | `config/github-repository-settings.json` | Live `delete_branch_on_merge: true`; confirm the merged PR branch is gone. |
| Protected current `main` | `config/github-repository-settings.json`, `scripts/github-repository-settings.mjs` | Active `main-protection` ruleset requires PRs, required checks strict/current with base, and blocks deletion and non-fast-forward pushes. No bypass actors. |
| Immutable release tags | `config/github-repository-settings.json`, `scripts/github-repository-settings.mjs` | Active `release-tag-immutability` ruleset covers `refs/tags/v*`, blocks update and deletion, and has no bypass actors. Never create a tag merely to test it. |
| Immutable GitHub Releases | `config/github-repository-settings.json`, `scripts/github-repository-settings.mjs` | Read the repository immutable Releases endpoint and require `enabled: true` before a new version publishes. A disabled setting fails verification; bounded settings application enables it. GitHub applies it only to future publications. |
| Read-only settings check | `scripts/verify-github-repository-settings.mjs` | `npm run verify:github-settings` reads repository metadata, immutable Releases, and rulesets with runtime `GH_ADMIN_TOKEN`, or `GH_TOKEN` when sufficiently privileged. Missing read access fails closed. |
| Bounded settings application | `scripts/apply-github-repository-settings.mjs` | `npm run apply:github-settings` changes only committed repository merge settings, immutable Releases, and the named rulesets, then performs an independent readback and comparison. Missing write/Administration access fails closed. Token values stay in process/provider secret state. |
| Release identity and publication | `.github/workflows/release.yml`, `scripts/release-contract.mjs`, `scripts/publish-release.mjs`, `docs/RELEASE-MANAGEMENT.md` | A separately authorized annotated `vMAJOR.MINOR.PATCH` tag must identify current `main` and the package/lock version. The tag workflow reproduces the archive, checks digest and attestation, and reconciles an immutable GitHub Release. No release is part of repository normalization. |
| Shared platform edge-code area | `config/phase.json`, `scripts/repository-contract.mjs`, `tests/repository-contract.test.mjs` | The `platform` grant is exactly path `platform/` for shared edge code only. `npm run check` accepts an absent or granted `platform/` directory, and fails on a missing or altered grant or on any of `src`, `app`, `apps`, `game`, `pages`, `public`, `workers` or `functions`. |
| Cloudflare desired state | `config/cloudflare.json`, `scripts/cloudflare-desired-state.mjs`, `tests/cloudflare-desired-state.test.mjs` | `npm run check` requires the exact closed shape: Workers `wizardgang`, `demo`, `sharktank` and `hexframe`, each owned by one repository's `production` environment; one custom-domain host per Worker plus `www` on `wizardgang` and no zone routes; one D1 and one R2 bucket named `wizardgang` with `<app>/` prefixes and lifecycle rules; no KV; only `demo:DemoCoordinator` and `sharktank:Room` Durable Objects and the demo's cron; one shared compatibility date and `nodejs_compat`; observability on and workers.dev and preview URLs off; Secrets Store names `WG_OPS_TOKEN` and `WG_SESSION_KEY`. It rejects unknown keys, duplicate hosts, admin-credential Worker secrets, account or binding IDs and secret value fields. The file is intent; `npm run verify:cloudflare` compares it live. |
| WizardGang secret registry | `config/secrets.json`, `scripts/secret-registry.mjs`, `tests/secret-registry.test.mjs`, `scripts/repository-contract.mjs` | `npm run check` requires every entry to carry exactly a name, kind (`secret`, `variable`, `derived`), home (`worker`, `secrets-store`, `github-environment`, `keychain`), consumers, provider, console credential and purpose. It rejects unknown keys and a secret not named `<PROVIDER>_<PURPOSE>_<KIND>` with the provider's prefix, except that a `github` name in a GitHub environment drops `GITHUB_`, which GitHub reserves for Actions names, and maps to the same console credential as its prefixed Worker form. It also rejects a GitHub-environment name that starts with `GITHUB_`, a public ID, issuer, URL or certificate stored as a secret, `CLOUDFLARE_API_TOKEN` or `CLOUDFLARE_ACCOUNT_ID` outside a GitHub environment, `WG_` outside the Secrets Store, a repository-level GitHub secret, a duplicate name in one home, a console credential shared by two names or a name with two credentials, and a derived key whose source is not `WG_SESSION_KEY`. An exception must name a registered consumer and its end condition. Each Worker's `secrets` and the Secrets Store list in `config/cloudflare.json` must equal the registry's, the Cloudflare deploy names must cover exactly the deploying `production` environments, and keychain consumers must be package scripts. The repository contract requires the registry, the validator and its tests. Nothing reads or writes a provider. |
| Read-only Cloudflare drift check | `scripts/verify-cloudflare.mjs`, `scripts/cloudflare-drift.mjs`, `scripts/cloudflare-live-state.mjs`, `tests/cloudflare-drift.test.mjs`, `tests/verify-cloudflare.test.mjs`, `tests/fixtures/cloudflare-2026-10-03.json` | `npm run verify:cloudflare` reads the account with runtime `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`, GET only, and compares by exact set equality: Workers, custom domains (host → Worker), D1, R2, KV, Durable Objects (Worker:class), crons, Worker secret names and Secrets Store secret names, plus each declared Worker's compatibility date and flags, observability, workers.dev and preview URLs, and the R2 lifecycle rules. It exits 1 on drift, 2 on missing or malformed credentials and 3 on denied read access, and never prints the token or account ID. No zone, DNS or ruleset reads. `npm run check` runs only the fixture tests, including the recorded 2026-10-03 account and its expected drift; the repository contract keeps the live read out of `check` and every workflow. |
| Registry-driven GitHub secret discovery and Cloudflare token rotation | `scripts/cloudflare-token-targets.mjs`, `scripts/discover-cloudflare-token-targets.mjs`, `scripts/rotate-cloudflare-token.mjs`, `tests/cloudflare-token-discovery.test.mjs`, `tests/cloudflare-token-rotation.test.mjs`, `tests/fixtures/fake-gh.mjs` | Targets come only from the `github-environment` entries and exceptions of `config/secrets.json`, in the repositories of `config/cloudflare.json`. Rotation requires `--credential <console name>`, accepts only a Cloudflare credential with a GitHub-environment target (`wg-cloudflare-deploy`) and writes only the secrets mapped to it, any registry exception included; an unknown or other credential exits 2 before any read or write. `npm run check` runs both commands against a stub `gh` executable and proves that each credential touches only its mapped targets and leaves the other's token unchanged; that no undeclared repository is read; that discovery reports every registry secret and variable and flags repository-level entries, another environment, an unregistered name, a missing environment or entry and an entry of the wrong kind; that the value travels only over `gh secret set` stdin, never in an argument, the environment or the output (a value pasted as an argument is not echoed); that nothing is read or written without `--apply`, a piped value Cloudflare reports active and existing mapped environments; and that a failed write, a failed re-read or an unchanged `updatedAt` fails the run while denied reads exit 3 before any write. The repository contract requires the exact package scripts and keeps them out of `check`, every other script and every workflow. |
| Owner-run Cloudflare provider runbook | [`docs/CLOUDFLARE-RUNBOOK.md`](CLOUDFLARE-RUNBOOK.md), `tests/cloudflare-runbook.test.mjs`, `tests/fixtures/runbook.mjs`, `scripts/repository-contract.mjs` | Every Phase 1 delete, Phase 3 provisioning step, the deploy rollback and each gated retirement lists a precondition, a command, a read-back and a rollback, in that order. `npm run check` proves that its relative links resolve, that every `npm run` it uses is a package script (including `verify:cloudflare`, `discover:cloudflare-token-targets` and `pbpaste \| npm run rotate:cloudflare-token -- --credential wg-cloudflare-deploy --apply`), that every rotation names a console credential the registry lets it rotate, and that every Worker, host, D1, R2, KV, Secrets Store, secret and repository it names is in `config/cloudflare.json`, `config/secrets.json` or the recorded 2026-10-03 inventory. It also proves that the step 3.4 lifecycle file equals the declared R2 rules, that its starting drift counts match the fixture, that step 1.5 greps only the Hexframe Worker source (`-- src`), and that it holds no account ID, binding ID or token value. Every command block and code span is self-contained, because each terminal run starts a fresh shell: it reads no variable it does not assign, runs wrangler only as `npx --yes wrangler@4.147.0`, reads the account ID only inline from `wrangler whoami --json`, and loops over exactly the `config/cloudflare.json` repositories. The repository contract requires the runbook and its test. The owner runs every step; no agent, workflow or `npm run check` mutates a provider. |
| Owner-run secrets runbook | [`docs/SECRETS-RUNBOOK.md`](SECRETS-RUNBOOK.md), `tests/secrets-runbook.test.mjs`, `tests/fixtures/runbook.mjs`, `scripts/repository-contract.mjs` | Every console credential in `config/secrets.json` (the four Cloudflare tokens, `wg-github-app` and the three OAuth clients), every registry secret without one (`WG_OPS_TOKEN`, `WG_SESSION_KEY` and both webhook secrets) and the SAML IdP application has a section that lists a precondition, mint and set, read-back, rotate, revoke and rollback, in that order; the retirements X1 to X4 list the four step parts. `npm run check` proves that its links and heading anchors resolve, that every `npm run` is a package script and both rotatable credentials rotate through `rotate:cloudflare-token`, that every registry name appears, that every Worker secret put and GitHub secret or variable write names a registry entry in its registry home and consumer, and that every demo Worker secret is put. The repository contract requires the runbook and its test. The owner runs every step. |

| Production boundary | `config/phase.json`, `README.md`, `docs/RELEASE-MANAGEMENT.md`, `scripts/repository-contract.mjs` | Application development is disabled in contract phase. Shared edge code under `platform/` is consumed by other repositories. This seed has no production target and never deploys a Worker itself. Its workflows must be exactly CI, Release, Release Cutter and the call-only `deploy-worker.yml`. None of its own workflows may call the deploy, run wrangler or bind an environment, and it may carry no wrangler dependency, config or package script. |

The GitHub settings scripts intentionally need only repository metadata and Repository Administration access to merge settings and repository rulesets. The release workflow's publication permissions are scoped to that workflow and are not required for repository settings verification or application. `npm run check` never reads `GH_ADMIN_TOKEN` or `GH_TOKEN`.
